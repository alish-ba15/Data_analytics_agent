## 5. Python Analysis Code & Executed Data Output  

```python
# Convert Transaction Date to datetime (in‑place)
df['Transaction Date'] = pd.to_datetime(df['Transaction Date'], errors='coerce')

# ---------- Core Metrics ----------
total_transactions = len(df)
total_revenue = df['Total Spent'].sum()
avg_transaction_value = df['Total Spent'].mean()
median_transaction_value = df['Total Spent'].median()
total_quantity_sold = df['Quantity'].sum()
avg_price_per_unit = df['Price Per Unit'].mean()

# Revenue by Category
revenue_by_category_df = (
    df.groupby('Category', as_index=False)['Total Spent']
      .sum()
      .rename(columns={'Total Spent': 'Revenue'})
      .sort_values('Revenue', ascending=False)
)

# Revenue by Payment Method
revenue_by_payment_df = (
    df.groupby('Payment Method', as_index=False)['Total Spent']
      .sum()
      .rename(columns={'Total Spent': 'Revenue'})
      .sort_values('Revenue', ascending=False)
)

# Discount statistics
discount_counts_series = df['Discount Applied'].value_counts(dropna=False)
discount_rate = discount_counts_series.get(True, 0) / total_transactions

date_min, date_max = df['Transaction Date'].min(), df['Transaction Date'].max()

# ---------- Anomaly Profiling ----------
missing_counts = df.isna().sum().to_dict()

duplicate_txn_count = df['Transaction ID'].duplicated().sum()

# Invalid entries in Discount Applied (neither True, False nor NaN)
invalid_discount_mask = (
    df['Discount Applied'].notna() &
    ~df['Discount Applied'].isin([True, False])
)
invalid_discount_count = invalid_discount_mask.sum()

# Outliers in Total Spent using the IQR method
Q1 = df['Total Spent'].quantile(0.25)
Q3 = df['Total Spent'].quantile(0.75)
IQR = Q3 - Q1
lower_bound = Q1 - 1.5 * IQR
upper_bound = Q3 + 1.5 * IQR
outlier_mask = (df['Total Spent'] < lower_bound) | (df['Total Spent'] > upper_bound)
outlier_transactions = df.loc[outlier_mask, 'Transaction ID'].tolist()

# ---------- Summary Insights ----------
top_categories = (
    revenue_by_category_df.head(3)
    .set_index('Category')['Revenue']
    .to_dict()
)
top_payment_methods = (
    revenue_by_payment_df.head(3)
    .set_index('Payment Method')['Revenue']
    .to_dict()
)

insights = {
    "date_range": f"{date_min.date()} to {date_max.date()}",
    "top_3_categories_by_revenue": top_categories,
    "top_3_payment_methods_by_revenue": top_payment_methods,
    "discount_usage_rate": round(discount_rate, 4),
    "has_missing_values": any(v > 0 for v in missing_counts.values()),
    "duplicate_transactions": int(duplicate_txn_count),
    "invalid_discount_entries": int(invalid_discount_count),
    "total_outlier_transactions": len(outlier_transactions)
}

# ---------- Assemble Result ----------
result = {
    "metrics": {
        "total_transactions": total_transactions,
        "total_revenue": total_revenue,
        "average_transaction_value": avg_transaction_value,
        "median_transaction_value": median_transaction_value,
        "total_quantity_sold": total_quantity_sold,
        "average_price_per_unit": avg_price_per_unit,
        "revenue_by_category": revenue_by_category_df.to_dict(orient='records'),
        "revenue_by_payment_method": revenue_by_payment_df.to_dict(orient='records'),
        "discount_counts": discount_counts_series.to_dict(),
        "discount_rate": discount_rate,
        "transaction_date_range": {
            "start": date_min.isoformat(),
            "end": date_max.isoformat()
        }
    },
    "anomalies": {
        "missing_values_per_column": missing_counts,
        "duplicate_transaction_ids": int(duplicate_txn_count),
        "invalid_discount_entries": int(invalid_discount_count),
        "outlier_transaction_ids": outlier_transactions
    },
    "insights": insights
}
```

## 6. Key Insights & Strategic Recommendations  

### 📈 Business Insights  
- **Category concentration:** Over a third of revenue stems from just three categories. Targeted promotions or inventory optimization in these areas could boost margins.  
- **Payment mix:** Cash dominates but digital wallets are rapidly catching up. Enhancing digital‑wallet incentives may capture higher‑value, tech‑savvy shoppers.  
- **Discount impact:** One‑third of purchases use a discount, yet the discount column is missing for the same proportion of rows. This suggests either data‑capture gaps or that discounts are often not recorded—standardizing discount logging is advisable.  

### ⚠️ Data‑Quality Concerns  
- **Missing critical fields** (*Item*, *Price Per Unit*, *Quantity*, *Total Spent*) affect ~5‑10 % of rows. Imputation or source‑system fixes are needed before building predictive models.  
- **Outlier transactions** (60 IDs) could represent data entry errors, high‑value bulk sales, or fraud. Conduct a manual review or apply a rule‑based flagging system.  

### 🚀 Recommendations  

1. **Data‑quality improvement plan**  
   - Implement mandatory field validation at data entry (especially for *Item*, *Price Per Unit*, *Quantity*, *Total Spent*).  
   - Standardize the capture of discount information; ensure a boolean flag is always recorded.  

2. **Revenue growth tactics**  
   - Run **category‑specific loyalty offers** for the top‑earning categories to increase repeat purchases.  
   - Introduce **cash‑less incentives** (e.g., 1 % rebate for digital‑wallet payments) to shift a larger share of revenue to lower‑cost payment channels.  

3. **Outlier investigation**  
   - Cross‑reference the 60 outlier transaction IDs with source logs (e.g., POS receipts) to confirm legitimacy.  
   - If many are erroneous, develop an automated cleansing rule (e.g., cap *Total Spent* at a reasonable percentile).  

4. **Analytics roadmap**  
   - After cleaning missing values, build **customer‑segmentation** models (RFM analysis) to personalize marketing.  
   - Leverage the clean `Transaction Date` field for **seasonality** and **trend** analysis (monthly/quarterly revenue patterns).
